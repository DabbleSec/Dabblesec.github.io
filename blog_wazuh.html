08.18.26 - Wazuh

Ola.

Welcome to my first project blog.

This week I have been building my own SOC using Wazuh.

Why?

A man on the Internet told me to do it.
In fact, the voices are many, and they all tell me practical experience is what I need.

Why Wazuh?

I'm poor. It's free. That's a good start.

But seriously... Wazuh provides open-source security monitoring and threat detection. File integrity monitoring. Configuration and compliance monitoring. Active response. Cool stuff.

If you're a glutton for punishment like me, then your workhorse of choice is an M1 MacBook, and the start of every project begins like this...

I'm too lazy to think up a fake name for Broadcom, so I used UTM. I already had it installed and, on the day I started this project, fresh exploits in VMware were published. So I gave it a miss.

Setting Up Wazuh

Setting up the Wazuh server was pretty easy. Grab an Ubuntu image. OpenSSH. Install. Bosh.

Next, get your Wazuh server IP, bang it into a web browser that will allow such witchcraft, and behold.

[Screenshots]

Deploying the Agents

Next, deploy your agents. Set up your endpoints. I chose to mix it up: Windows 11, macOS Tahoe, and another Ubuntu server.

Agents deployed.

Go to Wazuh. Refresh your page.

You now have eyes everywhere, but we need more.

Sysmon. Falco. Unified Logs.

Why not just Sysmon?

System architecture decided for me.

Testing

Create file. Delete file.
Create user. Delete user.
Generate logs. Check Wazuh.
Find log.

I'm not a stranger to SIEMs, but this isn't CyberOps.

Here, I started from scratch. Created a virtual network. Installed multiple operating systems. Deployed agents. Confirmed connectivity. Generated logs.

There is still plenty more to do.

This has been fun.

Until next time.

Au revoir.
